Getting started

  1. Choose a platform tab. Google Ads, X and Meta each hold their own working text, so nothing is overwritten when you switch.
  2. Paste or write your copy. Counts, remaining allowance and statuses update as you type.
  3. Read the two signals. Limit compliance tells you whether the copy fits. The Copy Readiness Score tells you how it reads.
  4. Save or export. Save a named copy set for later, copy a field or the whole set, or export plain text and a JSON backup.

Running locally: serve the folder over HTTP (for example npx serve .) so ES modules load. Opening the HTML files directly from disk will block module imports in most browsers.

Counting methods

Unicode code points

Each visible character counts as 1, including emoji and CJK characters. Used for Meta, where counts describe a display window rather than a submission rule.

Display width (Google)

Characters count 1, except double-width characters in Chinese, Japanese and Korean scripts, which count 2. Non-BMP characters such as emoji are also counted as 2 here — a conservative assumption the Google help pages do not specify.

X weighted length

Latin and most other scripts count 1, CJK characters count 2, emoji count 2, and every URL counts 23 regardless of real length. Computed by the bundled official parser, so parser-reported invalid characters surface as a warning too.

How the Copy Readiness Score works

Six checks, published weights, and a full deduction list. Limit compliance is deliberately excluded — see below.

Readiness checks, weights and what they penalise
Check Weight What it looks at
Scanability & sentence length25Sentences over 20 words, average sentence length, unbroken blocks of text.
Specificity & concrete detail20Numbers, time frames, prices and action verbs earn points; listed vague phrases and jargon lose them.
Capitalisation discipline15Words of four or more characters in full capitals, and fields that are mostly uppercase.
Repetition control15Content words used more than twice and repeated two-word phrases across the set.
Keyword coverage15Whether each optional target keyword appears. Excluded entirely when the keyword field is empty.
Message coverage10Required fields that contain text.

Weights re-normalise

If a check is unavailable it is removed from the denominator rather than scored as zero. An empty keyword field cannot lower your score. The interface lists which checks were excluded.

Compliance is separate

The readiness score never includes character limits. A message can fit perfectly and still be vague, so the app reports Within limit / Near limit / Over limit / Beyond display recommendation independently.

Grade bands

  • Strong 85–100
  • Good 70–84
  • Needs work 50–69
  • Weak 0–49

This score is a writing-quality heuristic built from transparent rules. It is not Google Ads Quality Score, not an approval, and not a performance forecast.

Previews

Previews rebuild an approximate layout — a Google search result block, an X post, a Meta feed card — with a mobile/desktop width switch. They exist to test reading order and first-glance impression.

The Google preview has two modes: As served shows up to three headlines and two descriptions, the most that can appear together; All assets lists every filled asset, which is how you audit the headlines and descriptions that will not be on screen at the same time.

Set the preview identity — brand name, X handle and domain — under the preview so the layouts read like your own account. It is stored in this browser and never leaves it.

They do not reproduce real rendering. Truncation depends on the placement, the device, the viewer's font-size setting, the language and the platform's layout engine. Always confirm in the platform's own preview tool before publishing.

Privacy and storage

  • All counting and analysis runs in your browser. There is no backend, no API key and no external service; the X parser is bundled locally.
  • Working copy, saved sets and settings live in localStorage under the mccc namespace. Nothing is transmitted anywhere.
  • Storage is not encrypted and not synced. Anyone with access to this browser profile can read it. Do not store confidential client copy on a shared machine.
  • Clearing site data deletes saved sets. Export a JSON backup first.
  • If storage is disabled or full, the app says so and keeps counting; only persistence is affected.
  • No cookies, no analytics, no trackers, no fonts or scripts loaded from third-party hosts.

Known limitations

  • Scope: standard X posts only — no premium long posts, threads or polls. Google Ads covers responsive search ad text assets, not Performance Max, Demand Gen or callouts. Meta covers one clearly labelled feed-ad preset.
  • Emoji on Google: Google does not publish how emoji are counted. This app counts them as 2, which can under-report your allowance. The live Google Ads editor is authoritative.
  • Thai and other combining scripts: Google documents double-width CJK only. Combining marks are counted per code point here; verify in the ad editor.
  • Meta numbers are recommendations. Ads Manager accepts far longer text; only the visible portion is counted here.
  • Keyword matching is a plain case-insensitive substring check, not stemming or semantic matching.
  • Accessibility: tested with keyboard navigation and screen-reader semantics, but not audited against every assistive technology combination.

Version and support

  • Build: v1.0.0. Platform rules reviewed 19 October 2026.
  • Offline: once loaded, the app installs a service worker and keeps working without a connection. A new release shows a “Reload to update” prompt instead of silently changing under you.
  • Backups: JSON exports are the supported way to move copy between browsers or devices. There is no account and no cloud sync.
  • Removing your data: Saved copy → Your data → Delete all data clears every saved set, working copy and setting from this browser.
